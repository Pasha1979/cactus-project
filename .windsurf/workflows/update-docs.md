# Обновление документации проекта

## Когда запускать
- После **3+ коммитов** в core-код
- После **исправления бага** — урок в `_extracted/lessons.md` + `v4/06_УРОКИ.md`
- После **завершения фичи** — отметить T-ID в `v4/01_ПЛАН.md` и `_extracted/tasks.md`
- После **TypeScript/Vercel ошибок** — задокументировать решение в уроках
- Перед **началом новой сессии** — проверить `v4/02_СТАТУС.md` и `01_ПЛАН.md`

## Чеклист обновления

### 1. Уроки (`_extracted/lessons.md`, сводка → `v4/06_УРОКИ.md`)
```
| L-N | [краткое описание] | Проблема: [что случилось] | Решение: [как исправили] | Предотвращение: [как избежать] | дата | источник |
```

### 2. План и задачи
- `v4/01_ПЛАН.md`: закрытые T-ID → ✅, новые задачи → «СЛЕДУЮЩИЕ»
- `_extracted/tasks.md`: статус + доказательство (вывод теста / хеш коммита)

### 3. Статус (только автоген!)
- `npm run brain:status` — `v4/02_СТАТУС.md` генерируется скриптом, руками НЕ править

### 4. Целостность
- `npm run brain:links` — 0 битых ссылок
- `npm run brain:regs` — реестры целые, все записи с источником

## Правило
> **Если я сделал значимое изменение — я ДОЛЖЕН обновить документацию ДО следующего ответа пользователю.**
