# Workflow: Обновление AI-мозга

При вызове этого workflow выполни:

1. Прочитай v4-ядро:
   - `v4/02_СТАТУС.md` — текущий статус
   - `v4/01_ПЛАН.md` — план и T-ID
   - `v4/06_УРОКИ.md` — уроки

2. Проанализируй что было сделано в текущей сессии (по истории чата)

3. Обнови файлы:
   - **`v4/01_ПЛАН.md`**: отметь закрытые T-ID, перенеси задачи «СЛЕДУЮЩИЕ» → «СЕЙЧАС»
   - **`_extracted/tasks.md`**: статус и доказательство (тест/коммит) по закрытым задачам
   - **`_extracted/lessons.md` + `v4/06_УРОКИ.md`**: если были ошибки/неочевидные моменты — урок
   - **`_extracted/decisions.md`**: если приняты архитектурные решения — D-запись с цитатой
   - **`v4/02_СТАТУС.md`**: НЕ править руками — перегенерировать скриптом (шаг 4)
   - **Сверка «вскользь»**: перебери сообщения пользователя за сессию на сигналы (вскользь, кстати, запомни, надо бы, хорошо бы, не забыть, а что если, ещё мысль, в будущем…) — всё ли записано в `_extracted/`? Пропущенное дописать сейчас через `npm run brain:add -- <тип> "<текст>" "<суть>" "<модуль>"` (R-14)

4. Перегенерируй статус и проверь целостность:
   - `npm run brain:status` — автоген `02_СТАТУС.md`
   - `npm run brain:links` — 0 битых ссылок
   - `npm run brain:regs` — все источники реестров резолвятся

5. Предложи топ-3 следующих шага по `v4/01_ПЛАН.md`

6. Сообщи пользователю что мозг обновлён и кратко резюмируй изменения

7. **Обязательно** гейт → коммит → пуш:
   - `flutter analyze` зелёный на Android И Windows (оба проекта, R-17)
   - `git add .`
   - `git commit -m "T-…: <краткое описание>"` (T-ID обязателен)
   - `git push`
   - Напомнить пользователю протестировать обе платформы и синхронизацию (R-33)

8. **Завершение сессии — ОБЯЗАТЕЛЬНО сгенерируй handoff:**
   - `npm run brain:sync` — одна команда: статус + checkpoint + handoff под текущий HEAD (читается первым при старте следующей сессии)
   - Страховка: git-хук `post-commit` (scripts/hooks/post-commit → .git/hooks/) перегенерирует handoff после КАЖДОГО коммита — файл остаётся изменённым и уходит в следующий коммит
   - `npm run brain:handoff-check` — индикатор протухания: ⚠️ «устарел на N коммитов» = надо перегенерировать (отставание на 1 — норма: сам коммит handoff сдвигает HEAD)
   - Закоммить обновлённый handoff вместе с финальными правками сессии — без этого шага сессия не считается завершённой
